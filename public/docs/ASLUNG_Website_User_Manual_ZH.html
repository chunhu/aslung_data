ASLUNG 網站完整使用與管理說明

版本日期：2026 年 10 月 22 日。適用對象：研究使用者、設備與校正管理人員、網站管理員及 EC2 維運人員。

本文件說明目前網站的登入、授權、量測查詢、校正、設備管理、HOBO 匯入與維運流程。操作前先確認帳號角色、資料授權及所選時區；刪除工作紀錄與永久清除量測檔案是不同操作。本文描述程式提供的功能，不代表每個環境已部署、DNS 已生效、排程已啟用或所有設備已成功下載。

一 網站連線與基本操作

正式環境請使用機構已完成 DNS 與 TLS 設定的 HTTPS 網址。預定網域為 https://api.lunglab.rcec.sinica.edu.tw；網域是否可用應由網管確認。不要將 127.0.0.1:3105 提供給其他電腦作為 EC2 網址，因為它指向各台電腦自己。

開啟 EC2 公用 IP 若出現 Welcome to nginx，表示已到達 Nginx，但該 IP 尚未路由至此應用。請由管理員設定反向代理或使用已核准的 SSH 通道；不要將 Docker 3000 埠直接公開。EC2 停止後再啟動可能改變未綁定 Elastic IP 的公用 IP，文件不把歷史 IP 視為永久連線位址。

登入後，側邊欄依角色顯示可用功能。上方可設定顯示時區與字級；語言按鈕切換中文及英文。日期輸入依所在表單標示的時區解讀，匯出 timestamp 通常為 UTC，尾端 Z 表示 UTC；臺灣時間比 UTC 快八小時。不要把畫面的破折號、CSV 空白或 JSON null 當成數字零。

二 帳號申請與個人設定

1. 新使用者可從登入頁申請會員，填寫姓名、Email、登入帳號、密碼、國家或地區、機構或團隊、計畫名稱及簡述。

2. 開啟驗證信並在驗證頁確認。驗證信有效期為 24 小時；重新寄送需原 Email 與密碼。

3. 等待管理員審核。Email 驗證與管理員核准是兩個步驟；核准帳號不會自動指派設備或檔案資料。

4. 登入後可修改密碼、補填我的合作資料，以及設定設備告警收信偏好。忘記密碼時由管理員透過終端工具重設。

公開申請需先設定 SMTP。未設定郵件服務時，系統會提示無法申請；管理員仍可另行建立帳號，並自行交付初始登入資訊。修改、重設密碼或停用帳號會使該帳號既有登入工作階段失效。請將 API Token 視為密鑰，勿貼入公開程式、文件或 Git。

三 角色與資料授權

角色管理功能量測資料存取
系統管理員 admin會員、設備、權限、校正、HOBO 與系統設定可存取全部資料
設備管理員 device_manager明確指定設備的狀態、部署、負責人與維修仍須另有資料授權
校正管理員 calibration_manager校正來源、同步、參數與版本仍須另有資料授權；背景工作管理僅 admin
研究會員 member個人設定與符合責任條件的維修紀錄依設備、地點及期間授權查詢與下載
檢視會員 viewer個人設定與允許的檢視功能可依授權查詢，禁止量測下載與批次匯出

角色、設備管理範圍、量測資料授權、維護身分及檔案授權分別處理。擁有設備管理權不等於擁有量測下載權；姓名相同也不代表維護權限相同。管理員在會員管理設定角色與設備範圍，在資料權限指派設備或地點授權，在維護身分關聯登記責任，在檔案專區指派檔案授權。

設備授權可限制起訖時間；地點授權會依設備在該地點的追蹤部署期間展開。查詢跨越未授權期間時應選擇正確的追蹤區段，或縮短期間。一般非 admin 帳號的 ASLUNG 查詢及下載範圍上限為 31 天；管理員不受此日期上限，但仍有各功能的處理與匯出限制。

四 即時線上狀態

即時頁顯示授權設備最新一筆紀錄、目前位置、連線狀態及 G3、GSA、溫度、濕度、CO₂、電池等原始值。電池取自 ch7，不在缺乏設備定義時假定為百分比。可搜尋設備或位置、手動更新及調整更新頻率；管理員可設定全站預設，一般會員調整自己的瀏覽器更新頻率。

未部署且超過一年未回報的設備會從即時清單隱藏，並非刪除設備。已部署但長期離線的設備仍顯示。管理員可手動搜尋近 1、7、30 或 365 天未建檔設備，最多顯示 200 台，查看最新量測後補登；補登不會自行建立會員資料授權。

五 ASLUNG 資料查詢與批次下載

1. 開啟資料查詢，以可搜尋設備選單選擇設備及追蹤區段。

2. 確認可下載資料期間，設定開始、結束時間與時區。

3. 選擇原始資料、原始值加即時計算係數，或完成清理與校正的六項規則結果。

4. 按查詢資料，依畫面的載入、成功或錯誤訊息處理。欄位資料說明按鈕可另開中英文欄位文件並下載。

5. 選擇單次或多筆條件批次匯出。批次下載會整合成 ZIP，並附中英文 download_manifest.txt，不必逐日手動按下載。

ASLUNG 的 CSV 與 JSON 完整下載均由伺服器產生 ZIP，不要把 ZIP 直接當純 CSV 讀取。檔名以設備與臺灣日期命名；不同追蹤區段可能附區段識別，避免重名。分頁查詢顯示的是部分資料，下載才合併所選授權範圍內的資料；批次清單會列出失敗或缺少成果的項目，匯出成功不代表所有通道均有有效校正值。

一般查詢起訖均包含；背景每日處理工作使用開始包含、結束不包含的區間。例如處理 10 月 1 日，工作結束時間是 10 月 2 日零時。匯出格式與欄位依模式及結果版本而異，請保留清單、規則版本及品質旗標，讓分析可追溯。

六 校正模式與欄位解讀

模式來源與用途重要限制
raw 原始值查詢 MySQL 原始量測與易讀欄位別名不套用校正係數
both 即時計算係數保留原值，依時間及通道計算 slope × raw + intercept不執行完整六項清理；保留負校正值
processed 六項規則成果讀取已完成且授權足夠的背景結果缺少完整覆蓋時回報錯誤，不以原始值補齊

*_clean 是清理值，*_calibrated 是套係數後的值，*_final 包含後續 PM1 上限與第六項規則，另有 _quality、_background_status、處理版本及工作識別。新版本保留完整原始欄位及易讀名稱；舊檔缺少的欄位不會即時從 MySQL 補回，需要重新計算新版本。

NO_FACTOR 表示該設備、通道及量測時間沒有適用係數，不等於原始量測無效。INVALID_RAW 表示原值無法解析成有限數值；有限的十進位數字字串可供新版計算。FACTOR_CONFLICT 或 CONFLICT 表示係數重疊或不唯一。CLEAN_MISSING 表示清理後缺值，NEAR_EQUAL_NOT_EVALUABLE 表示第六項無足夠原值判斷。NO_Factoe 是常見拼字誤寫，正式狀態為 NO_FACTOR。

六項規則依序處理三個 PM 同值異常及低值、Ghost Peak、溫濕度與 CO₂ 低值、係數校正、PM1 不高於 PM2.5，以及高 PM1 近同值排除。G3 與 GSA 分開處理；完整規則中的負校正值留空。品質旗標可在同一筆、多個通道重複出現，不能把摘要次數直接相加當作刪除資料列數。

七 校正來源與背景工作

在校正管理為每個 Google 試算表分頁建立獨立來源，填寫網址、名稱與說明。立即同步只處理該來源。必要表頭包括 aslung_id, PM, slope1, intercept1, Start_date；第二段與結束日期為選填。PM1、PM2.5、PM10 對應 G3，GSA 有各自通道；PM125 與 UNMAPPED 僅保留查詢，不猜測用途。

來源日期以臺灣時間解讀，內部採開始包含、結束不包含。未填 End_date 時可銜接同來源下一筆開始日期；合法同日交接採新參數當日生效。錯誤、重複開始時間或衝突會拒絕整次更新並保留上次成功版本。查看匯入紀錄可下載完整錯誤報告及來源版本，不必只依來源卡片的簡短訊息判斷。

啟用來源每日臺灣時間 02:00 檢查，停機後會補查。私人表單需伺服器唯讀服務帳號與試算表檢視權限；勿將憑證提交 Git。停用來源保留歷史，但不再用其目前參數校正。

背景清理與校正由 admin 管理：選設備、起訖、預設為 3 的 up_limit，建立最多 31 天的每日工作；可重新計算新版本。全域排程需明確啟用，03:00 後檢查最近三個完整日，舊歷史需手動建立。worker 未執行時工作停留排隊。工作紀錄支援設備、日期、狀態及每頁 20 筆；詳細資料內先查看版本與品質，再手動載入預覽或下載單日成果。

八 設備庫 追蹤與維護人員

設備庫提供狀態、地點、負責人、連線及品質篩選，支援設備履歷、CSV 匯出、QR Code、快速更新及批次操作。狀態或移轉操作可能結束目前部署；操作前先核對生效時間與影響範圍。已有維修履歷的設備不可直接刪除，可改為報廢等狀態保留紀錄。

地點庫保存 Lab ID、地理與站點描述；設備追蹤以設備、地點、開始與結束時間保存部署歷史。從 Google 或 CSV／TSV 匯入時，依選擇來源、對應欄位、預覽、套用的順序處理。來源未列出的歷史不會因同步自動刪除。負責人尚未建檔只提示警告，仍保留姓名匯入；之後應補齊聯絡資料。

維護人員可填中文與英文稱呼、主要及測試信箱等資料。中文介面保留原姓名，英文介面優先顯示英文稱呼。管理員另以維護身分關聯或明確 Email 綁定會員；資料下載授權與設備維護責任不可互相推定。

九 維修保養

可建立故障維修、定期保養、校正及更換零件紀錄，依待處理、處理中、待驗收、已完成流程更新，或填原因取消。保留建立時部署與維護人員快照、承辦人、廠商、費用、處理與驗收歷程。

管理員可視操作將設備改為維修並結束部署，驗收後改待命不代表自動重新部署。其他未結案維修單會限制提前改狀態。結案後以追加說明更正，不覆寫結案內容。附件接受 PDF、PNG、JPEG、WebP，每檔 5 MB、每單 20 檔，保存在 SQLite 並隨資料庫備份。

一般帳號須符合目前部署責任、原建立人、指定承辦或角色與設備管理範圍條件；viewer 不可寫入。只有量測讀取授權或同名不能取得維修寫入權。第一階段提供到期畫面提醒，不會自動建立週期保養單或發送保養到期信。

十 告警通知與檔案專區

管理員設定 SMTP、檢查頻率、時區與離線門檻，再啟用告警。收件人依設備目前維護責任與聯絡資料決定；會員收信偏好只控制設備告警，不控制註冊驗證與審核信。從未回報或最後回報早於一個曆年的設備可能仍顯示警示，但不列入告警寄信；查詢失敗記為狀態未知。

測試信模式仍遵守主要聯絡會員停收設定。請從告警日誌分辨偵測、略過、寄送成功與失敗；通知負責人數以實際寄送結果為準。SMTP 修復後需另檢查註冊或審核郵件狀態。

檔案專區讓 admin 上傳檔案、附說明並指定會員授權；會員僅能檢視或下載已授權檔案。檔案授權獨立於量測資料授權。網站檔案實體另存本機，僅備份 SQLite 不等於已備份這些檔案；維修附件則在 SQLite 內。

十一 HOBO 設備與歷史匯入

HOBO 功能目前僅供 admin。伺服器在 .env 設定 LICOR_API_TOKEN，不是讓一般會員輸入該 Token；ASLUNG 個人 API Token 與 LI-COR Token 不可互換。

1. 使用可搜尋下拉選單挑選設備，只顯示單台同步狀態與本機／S3 筆數。

2. 展開新增、歷史匯入與排程設定。批次區預填本次提供的 24 台序號，可編輯；首次起日為 2025/01/01 臺灣零時，至按鈕執行當下。

3. 核對 Logger Serial Number、名稱、起日及是否啟用每小時同步，再儲存或排入匯入。

4. 在同步工作查看月份、日游標及錯誤。每台依臺灣日曆月分段，月內每次請求最多一天；S3 仍按設備日歸檔。

全部設備預設共用 15 秒 API 請求間隔，含超量後的切分請求；完成一個月後該設備暫停 60 秒。429 或 509 會全域退避至少 5 分鐘，連續限流可增至 60 分鐘，且遵守較長的 Retry-After。進度與下次請求時間保存在 SQLite，重啟後可續傳。這些間隔是程式保守預設，不代表 LI-COR 承諾的額度。

收到 max_results 時繼續切分時間，不把截斷資料當完整成果；單秒仍超限則顯示失敗。HTTP 200 且 data 空白只代表該查詢沒有回傳資料，不足以證明全部歷史存在或設備權限完整。一般失敗最多三次後需重試；限流不耗用這三次額度。既有 HTTP 400 不應只靠連續重試處理，需確認序號、日期與 LI-COR 的實際錯誤條件。

十二 HOBO 搜尋 取消與刪除

獨立資料搜尋區可依設備、所選時區起訖、量測項目、感測器序號及關鍵字查詢已匯入的本機與 S3 資料。條件共同篩選；資料關鍵字亦可搜尋其他量測項目、單位、數值與資料類型。每頁 200 筆，載入更多保留相同條件；完整 CSV 下載套用相同條件，為直接 CSV，不是 ASLUNG 的 ZIP。修改條件會清除舊結果與下載連結。

HOBO 採長表，每列是一個感測器的一次量測，欄位包括 logger_sn、sensor_sn、timestamp、sensor_measurement_type、value、unit、data_type、data_type_id。原單位保留，例如溫度、相對濕度、露點、風、雨、PAR、日射量、電池；不轉為 ASLUNG PM 欄位，也不套用其校正係數。

操作會移除或停止會保留
取消工作或批量取消後續下載與重試，並停用對應設備同步已下載量測、已完成進度與工作紀錄
刪除工作紀錄或批量刪除所選非執行中工作與月份紀錄設備、本機量測、S3 檔案與索引
清除 HOBO 資料所選臺灣整日的本機量測、S3 歷次檔與版本及相關紀錄設備、清除稽核、另存備份與電腦已下載檔案

批量全選僅涵蓋目前最近 30 筆清單，確認視窗固定工作 ID。排隊中、同步中及失敗工作可取消，已完成或已取消者略過。刪除紀錄需先取消仍活躍的工作，再輸入 DELETE；一筆不符合時整批拒絕刪除。執行中取消會嘗試中止 HTTP，取消後未發布的回應不寫入資料庫。

永久清除先選設備與臺灣整日起訖、預覽、輸入 DELETE。系統先備份 SQLite，再停用排程、取消未完成工作，worker 逐設備日清空 S3 歷次版本與標記，成功後刪本機與索引。權限或部分刪除失敗時保留本機及索引重試。預覽 15 分鐘有效，每批最多 20,000 個設備日；預覽的 S3 數量為索引範圍，不是歷次版本的精確總數。清除完成後重新啟用同步或手動匯入仍可能抓回相同原站資料。

十三 ASLUNG 成果清除

管理員在校正工作記錄套用設備、日期及狀態篩選，再預覽清除。範圍跨所有分頁，每批最多 500 個工作，排除執行或上傳中項目。確認需 DELETE，預設同時停用全域及所選設備排程。

備份 SQLite 後，由 worker 清除本機成果、對應 S3 所有版本、相關工作與查詢快照；失敗保留可重試狀態。原始 MySQL 量測、會員、設備與係數不刪除。備份、電腦已下載 ZIP、無工作記錄的孤立檔案及 processed/_checks 不包含於此清除。永久刪除 S3 成果不能只靠 SQLite 備份還原。

十四 API 與程式分析

在資料串接產生個人 API Token，外部程式以 Authorization: Bearer <TOKEN> 呼叫 /api/data；已登入同源瀏覽器可用 Session Cookie。Token 不會擴大資料權限，viewer 仍無量測下載權。撤銷 Token 會使使用它的程式失去存取能力。

查詢需帶 aslung_id、start、end，可用 cursor 分頁、segment_id 指定區段、calibration 選 raw／both／processed。完整下載加 download=1 與 format=csv 或 json，收到的是 ZIP；不要直接把 response.text 當量測 JSON。both 與 processed 應沿用回傳的 calibration_snapshot，讓同一查詢或下載版本一致。

HOBO /api/hobo 另提供 query 與 csv，僅 admin，可用 measurement、sensor、q 篩選；這不是 LI-COR 原站 API。完整參數與可執行範例見同目錄的中英文 API 使用說明。

十五 部署與儲存管理

目前 ASLUNG 原始量測由後端以 MYSQL_HOST、MYSQL_USER、MYSQL_PASSWORD、MYSQL_DATABASE 直接讀 MySQL rawdata；不是舊文件所述的待開發外部量測 API。SQLite 保存帳號、權限、部署、校正及 HOBO 設定、進度與索引。校正成果以 CALIBRATION_STORAGE 控制本機或 S3；HOBO 另以 HOBO_STORAGE 控制。

S3 使用 EC2 Role。讀寫分別限定 processed/* 與 hobo/*；清除另新增 scripts/iam-calibration-cleanup.json、scripts/iam-hobo-cleanup.json 的補充政策，保留原讀寫政策。範本桶名需依環境調整；勿建立或公開長期金鑰。

cd ~/aslung-deployment/aslung_data
sudo bash scripts/deploy_cal.sh
sudo docker compose --profile calibration ps -a
curl -sS --max-time 15 http://127.0.0.1:3000/api/health

部署腳本先建置、檢查、備份再更新網站與 worker；不會自動啟用資料庫中未開啟的排程。修改 .env 後需重新建立容器，只有 restart 不會載入新的容器環境變數。手動停止的 worker 需明確啟動；開機恢復依 Docker、Nginx 與容器 restart 設定，不能僅靠主機已開機推定網站正常。

HOBO S3 按設備日驗證上傳後移除本機暫存，既有本機量測會由 worker 漸進搬移；校正成果目前仍保留本機檔案作恢復或快取。HOBO 的舊 S3 世代檔會保留至清除，須監控用量。刪除 SQLite 列只釋放可重用頁面，不保證立即縮小磁碟檔案。

十六 備份與問題排查

備份至少涵蓋 SQLite、一般上傳檔案、校正成果、S3 量測物件及受保護的設定；SQLite 熱備份不包含外部檔案或 S3 物件。請保留異地副本並測試還原。還原前停止 app 與 calibration-worker，完成檔案與 WAL 一致性處理後才啟動；不要在 writer 執行時直接覆蓋資料庫。具體命令見部署指南。
