# HOBO / LI-COR 資料匯入

管理員登入後，從側邊欄開啟 **HOBO / LI-COR**。本功能使用 [LI-COR 官方 API](https://api.licor.cloud/v1/docs/) 的 `GET /v1/data`，以 Bearer Token、Logger Serial Number 和 UTC 起訖時間下載感測資料。

## 部署與設定

1. 在 EC2 專案的 `.env` 新增 `LICOR_API_TOKEN=<您的 Token>`。請勿使用 `NEXT_PUBLIC_` 前綴，也不要將實際 Token 提交至 Git。

   若使用 S3，額外設定：

   ```dotenv
   HOBO_STORAGE=s3
   HOBO_API_INTERVAL_MS=15000
   HOBO_MONTH_PAUSE_MS=60000
   AWS_REGION=ap-northeast-1
   S3_BUCKET=aslung-calibration-prod-20261020
   ```

   預設 `HOBO_STORAGE=local`，與校正成果的 `CALIBRATION_STORAGE` 分別控制。HOBO S3 模式使用現有 EC2 IAM Role，需對 `hobo/*` 有 `s3:GetObject` 與 `s3:PutObject` 權限。
2. 部署更新，讓 app 與 calibration-worker 都讀取新設定：

   ```bash
   cd ~/aslung-deployment/aslung_data
   sudo bash scripts/deploy_cal.sh
   ```

   若映像已更新，只改了 `.env`，可重新建立容器：

   ```bash
   sudo docker compose --profile calibration up -d --force-recreate app calibration-worker
   ```

3. 開啟 HOBO 頁面，以可搜尋的下拉選單選擇既有設備，可輸入序號或名稱縮小清單；頁面僅顯示所選設備的同步狀態、資料筆數與最新量測，預設不展開全部設備資料列。勾選「顯示全部設備摘要」可查看所有已建檔設備的每小時同步啟用／停用狀態、目前工作狀態（排隊中／同步中／目前無執行工作）、本機筆數、S3 筆數、第一筆與最後一筆時間（UTC），包括尚無資料的設備；排程與工作狀態隨頁面約每 15 秒更新；啟用排程不代表當下正在下載，手動匯入亦可能在排程停用時執行。按「更新摘要」取得最新筆數與時間範圍。設備標題的台數依已建檔清單動態計算，新增設備後會增加，並非固定 24 台。本機暫存與 S3 可能重疊，筆數不可直接相加；筆數以感測器量測紀錄計算。新歸檔會保存精確第一筆時間索引；舊歸檔首次查閱時僅讀取各設備最早一天的 S3 檔案並快取索引，不重新呼叫 LI-COR。讀取失敗時顯示該設備的錯誤，可稍後更新摘要重試。新增設備時展開「新增、歷史匯入與排程設定」，填入 LI-COR 網站上的 **Logger Serial Number**（不是感測器序號）、設備名稱，以及開始、結束時間。先儲存設備，再按「匯入指定範圍」。官方文件沒有提供列出所有設備的端點，因此新增時需要手動輸入序號。
4. 查看同步工作狀態。完成後在獨立的「HOBO 資料搜尋」區塊選擇設備及起訖時間，按「搜尋資料」，再按「下載全部符合資料（CSV）」。查詢每頁 200 筆，CSV 包含全部符合搜尋條件的已匯入資料，不限目前顯示頁面。

### 資料搜尋條件

- 設備：可輸入設備序號或名稱搜尋下拉選單；資料搜尋可獨立選擇設備，也會隨上方主設備選取更新。
- 日期：依網站選取時區輸入，送到 API 時換算 UTC；結果及 CSV 時間保留 UTC。
- 量測項目：下拉選擇溫度、相對濕度、露點、風向、風速、陣風、PAR、日射量、降雨、電池，或全部。
- 感測器序號：輸入完整或部分 Sensor SN，不區分大小寫。
- 資料關鍵字：比對原始欄位中的量測名稱、單位、數值、資料類型等文字，不區分大小寫；可搜尋下拉選單尚未列出的其他量測項目。
- 各條件共同篩選；本機與 S3 合併去重後再套用條件與分頁，CSV 使用相同條件。修改條件會清除舊結果與下載連結，避免混用不同搜尋結果。
- API 的 `action=query`／`action=csv` 共同支援選填 `measurement`、`sensor`、`q` 參數，每個搜尋文字上限 160 字。

新增／批次匯入與排程設定、清除設定預設收合；同步工作與查詢結果使用固定高度的捲動區域，避免清單將頁面拉得過長。

### RCEC 24 台初始清單

批次新增區塊預填使用者提供的 24 台序號，來源清單為 `lib/hobo-rcec-loggers.json`。初始起日為 **2025/01/01 00:00 Asia/Taipei**，送至 API 的 UTC 起日為 **2024/12/31 16:00**；結束時間為按下按鈕當下。清單及日期均可在送出前修改。

按「儲存並從起日匯入至今」會一次建立設備與工作，每台以 `RCEC_序號` 命名。已有執行中工作的設備會跳過建立新工作、保留原進度。勾選「同時啟用每小時同步」才會延續定期抓取。此按鈕會儲存所選同步設定，請在送出前確認勾選狀態。

24 台會按日輪流抓取，避免第一台的長期歷史阻塞其他設備；長期歷史需要多次 API 請求，排隊與抓取進度會保留。各台獨立請求，不依賴 LI-COR 對大量序號合併查詢的支援。

LI-COR 對指定區間無資料時可能仍回覆 HTTP 200，因此空結果不等同於設備存取權限已確認，也不代表設備完全沒有歷史資料。

## 定期同步

- 預設關閉；勾選「每小時同步」並儲存設備才會啟用。
- 首次從新增設備時的開始時間抓到目前時間，依臺灣日曆月份分段，月內以一天以內區塊輪流下載；跨一年或更長歷史不會一次送給 LI-COR。之後每小時補抓最近一天，更新可能延遲回傳的資料。
- 月份進度保存在 `hobo_months`，介面顯示已完成月份、目前月份及每日續傳游標。舊版已排隊的長期工作會從既有游標接續，不會重抓已完成的月份。每個月完成後，該設備預設暫停 60 秒再進入下個月，其他設備仍遵守共用請求間隔。
- 全部設備共用至少 15 秒的 LI-COR 請求間隔，包含資料量超限後的切分請求。下次可請求時間保存在 SQLite，worker 重啟後仍沿用；限速僅影響 LI-COR API，不會讓整個背景 worker 閒置等待。單一工作內切分請求需要等待時，會暫留在該工作。
- HTTP 429／509 會暫停全部設備至少 5 分鐘，連續遇到時依序延長至 10、20、40、60 分鐘；若 `Retry-After` 要求更久則依其等待。這類限流不消耗一般失敗的三次重試額度，日游標保留原位。
- 新增設備後，首次同步起日固定；欲補抓更早或更久之前修訂的資料，使用指定範圍匯入。
- 背景工作每次處理一台設備的一日區間，與校正 worker 共用程序。worker 停止期間不會同步，重新啟動後會續傳。上游逾時或資料密集時可能延後其他背景工作。
- 上游回覆 `max_results=true` 時，捨棄截斷內容，切分時間區間重新下載；若單秒資料仍超限，顯示失敗，不把截斷的資料視為完成。
- 同步工作有鎖定與持續進度，一般失敗最多自動嘗試三次；之後可按「重試」。已成功完成的區塊保留，失敗區塊不推進進度。
- 重疊資料以設備、感測器、時間、資料類型 ID、量測類型、單位為識別，更新原值，不累積重複紀錄。工作「已抓取筆數」含重疊，設備資料筆數才是去重後總數。

### 取消同步工作

在「同步工作」的排隊中、同步中或失敗工作旁按「取消工作」，確認後會：

- 將工作標記為「已取消」，停止後續月份、下載與自動重試，保留已完成進度與已下載的本機／S3 資料。
- 停用該設備的每小時同步，避免排程立即重新排入同一段歷史；不影響其他設備。
- 對執行中的請求，每秒檢查取消狀態並嘗試中止連線；請求間隔等待亦會中止。已送出的請求可能仍由 LI-COR 處理，但取消後尚未發布的回應不會寫入資料庫，也不會繼續切分下載。
- 「已完成」工作無法取消；需要移除已下載資料時，使用下方清除功能。「已取消」工作不會以重試恢復，欲再次匯入請建立新的指定範圍工作；欲自動同步需重新勾選並儲存排程。

### 批量取消與刪除工作紀錄

- 同步工作左側可逐筆勾選，表頭可全選目前清單（最近 30 筆），不會操作未列出的其他工作；API 每批上限 100 筆。
- 「批量取消」經確認後，取消所選排隊中、同步中及失敗的工作，停用這些設備的自動同步；已完成或已取消工作會略過並回報數量。保留本機與 S3 量測資料。
- 「批量刪除紀錄」僅適用於失敗、已取消或已完成的工作。選取中若包含排隊／同步中的工作，需先批量取消，再重新勾選刪除。單筆亦可按「刪除紀錄」。
- 刪除前核對工作數與設備，輸入 `DELETE`；刪除工作及月份進度紀錄，保留設備、量測、S3 物件及每日索引，既有查詢與 CSV 下載仍可使用。刪除已完成紀錄不會停用該設備既有排程。
- 確認視窗固定本次工作 ID，清單自動刷新不會改變範圍。伺服器會再次檢查狀態，若有工作已消失或仍在執行，整批刪除不會進行。
- 若要連同量測資料與 S3 檔案一起刪除，使用「清除 HOBO 資料」，不使用工作紀錄刪除。

## 資料與權限

- 目前查詢、設定、同步、下載皆僅供系統管理員使用，獨立於 ASLUNG 會員設備授權及 PM 校正流程。
- 本機模式的感測資料存於持久化 SQLite 的 `hobo_observations`。S3 模式中這張表僅作待歸檔暫存；設備及排程在 `hobo_loggers`，工作進度在 `hobo_jobs`。不寫入既有 MySQL rawdata。
- CSV 保留官方欄位：`logger_sn`、`sensor_sn`、`timestamp`、`data_type`、`data_type_id`、`value`、`unit`、`sensor_measurement_type`。資料以長表格式輸出，每列是一個感測器的一次量測；不猜測單位、不轉換成 ASLUNG PM 欄位。
- 輸入時間依網站目前選取時區換算 UTC；CSV timestamp 保留 UTC，檔名日期以 Asia/Taipei 計算，例如 `HOBO_10665731_20261001_20261021.csv`。
- Token 只由伺服器環境變數讀取，不回傳瀏覽器，不儲存在資料庫、CSV 或工作錯誤訊息中。

## S3 歸檔、搬移及查詢

- 啟用 S3 並啟動 worker 後，既有本機量測會自動按臺灣時間的設備日搬移；不需要重新下載 LI-COR 歷史資料。每個 worker 回合最多歸檔兩個設備日，再處理一次新資料同步。
- 路徑格式：`hobo/<Logger Serial>/<YYYY>/<MM>/<DD>/<generation UUID>/<sha256>.jsonl.gz`。每個設備日的目前檔案索引保留在 `hobo_archives`；上傳前也會記錄每日範圍，以便清除中斷後留下的孤立上傳。
- 上傳以 AES256 加密並附 SHA-256 檢查碼，HEAD 驗證檔案長度、檢查碼、metadata 全部一致後，才以 SQLite transaction 發布索引及移除已搬移的暫存列。失敗時本機資料保持完整；worker 暫停新資料下載，先重試歸檔，頁面會顯示錯誤。
- 同步更正會與現有 S3 設備日合併、去重；僅資料新增、更正或儲存位置變更時產生新的不可變檔案並發布索引。完全相同的重複同步會驗證既有 S3 內容後沿用原檔，只移除重複的本機暫存，不再新增 S3 世代檔。歷次檔案暫不自動刪除，會產生額外 S3 用量；下方同步清除涵蓋該日所有歷次檔案與版本。
- 查詢與 CSV 依日期讀取、驗證、解壓 S3 檔案，並合併本機尚未歸檔的較新值。每次在記憶體處理一個設備日，不把整段歷史或已歸檔資料重新存回 SQLite。
- 單日壓縮檔上限 64 MiB、解壓上限 128 MiB，超出上限會停止並保留本機資料。
- 移除 SQLite 量測列會釋放資料庫內可重用的頁面，但不自動縮小既有 SQLite 檔案；此流程不會在正式站執行 VACUUM。
- SQLite 備份包含索引與設定，**不包含 S3 量測物件**。請依機構需求另規劃 S3 的備份或保留政策。

## 重複資料判定與處理

以 `logger_sn + timestamp + sensor_sn + data_type_id + sensor_measurement_type + unit` 作為唯一鍵。來源時間會正規化為 UTC，保留觀測的毫秒精度。同時間的不同感測器、量測項目、資料類型 ID 或單位，仍是各自獨立的資料；不能只按時間或量測數值刪重複。

- 相同唯一鍵且數值、資料類型文字均相同：SQLite 不新增，也不重寫原紀錄。適用單次回應重複、每日交界及定期重抓重疊期間。
- 相同唯一鍵但來源修正數值或資料類型文字：更新原紀錄；不是另外新增一筆。零與空值分開處理。
- S3 與本機同時存在相同唯一鍵：查詢及 CSV 合併成一筆，以較新的本機同步值優先，歸檔後沿用相同規則。完全相同的設備日不重複上傳；內容讀取或檢查碼驗證失敗時保留本機暫存，不能當成重複而刪除。
- 同步工作「已抓取筆數（含重疊）」是來源回傳累計，不是新增筆數；不能以此判斷資料庫有重複紀錄。本機與 S3 筆數在歸檔完成前也可能涵蓋同一觀測，不能直接相加當作去重後總筆數。

建議保留既有歷次 S3 更正版本以供恢復；這次防護不回頭刪除歷史檔案、備份或 LI-COR 原站資料。若要處理既有多餘版本，應先盤點目前索引與保留需求，再另行規劃清理，不要直接刪除整個日期前綴。

English: Observation identity consists of logger, UTC timestamp, sensor, data type ID, measurement type and unit. Identical observations are no-ops; corrections update the existing record. Queries and CSV merge local and archived observations by the same identity. An unchanged verified daily S3 archive is reused instead of uploading another generation. Different sensors or units must not be collapsed merely because their times or values match. Fetched job counts include overlap and are not counts of new unique observations.

## 清除 HOBO 測試資料（本機＋S3）

1. 除原有讀寫政策外，在 `EC2-SSM-Role` **新增**內嵌政策 `aslung-hobo-s3-cleanup`，JSON 使用 `scripts/iam-hobo-cleanup.json`，保留所有原有政策。此政策僅允許讀取儲存桶版本設定、列舉 `hobo/*` 版本，及刪除 `hobo/*` 物件／版本；不允許刪除 `processed/*`。
2. 在 HOBO 頁面下方「清除 HOBO 資料」選擇單台或全部設備，以及臺灣時間的開始、結束日期。結束日期包含整日；每批最多 20,000 個設備日。
3. 按「預覽清除範圍」。預覽以本機索引統計本機量測、S3 索引量測、每日 S3 範圍及目前檔案大小；不向 S3 逐筆列舉版本數，亦不是所有歷次版本容量的精確統計。
4. 核對範圍，輸入 `DELETE` 並確認。預覽綁定操作者、15 分鐘有效；資料有變更時必須重新預覽。
5. 系統先建立資料庫備份，之後停用所選設備的自動同步、取消未完成匯入工作，排入持久化清除佇列。若同步／歸檔正在執行，確認會回覆忙碌，請稍後重試。清除期間禁止重新啟用排程或匯入所選設備。
6. worker 每次處理一個設備日：刪除該範圍在 S3 的所有歷次檔案、物件版本與刪除標記，確認已空，再清除本機量測及索引。失敗保留本機資料與索引、顯示原因，會自動延後重試，也可按「立即重試」。清除中的設備日不允許查詢或下載。
7. 完成後保留設備設定與清除稽核，移除所選範圍相關的同步工作記錄。自動同步保持停用；日後手動匯入或再次啟用排程仍可能重新抓回相同資料。

本功能不刪除 LI-COR 原站資料、ASLUNG 校正成果、既有資料庫備份，或電腦已下載的 CSV。S3 永久版本刪除無法從 SQLite 備份還原量測檔。
